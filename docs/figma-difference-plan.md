## الخلاصة التنفيذية

الدمج بين `main` و`dev` مكتمل، وجميع التعارضات حُلّت. الحالة البرمجية الأساسية سليمة: نجح TypeScript، ونجحت الاختبارات بعدد **171 اختبارًا ناجحًا و0 فشل**، ونجح Production Build بعد حذف cache الخاص بـ Next.js وإعادة البناء من الصفر.

لكن المطابقة البصرية ليست 100% بعد. نتائج المقارنة المتاحة تغطي ثماني لقطات فقط. جميع هذه اللقطات تتجاوز حد المطابقة المقبول وهو أقل من 1% من البكسلات المختلفة. كما أن معظم صفحات الإدارة، وصفحة تسجيل الدخول، وتفاصيل الأخبار، ونسخ الهاتف لبقية الصفحات لم تدخل المقارنة البصرية بعد.

> **النتيجة الحالية:** الكود مدموج ويُبنى ويجتاز الاختبارات، لكن لا يجوز اعتماد الواجهات بصريًا بنسبة 100% قبل تقليل فروقات البكسل وإضافة قياسات للمسارات غير المقاسة.

## ما تم إصلاحه بالفعل

تم دمج تحديثات التعريب الموجودة في `main` مع إصلاحات Figma الموجودة في `dev`. أصبحت الفروع متطابقة، وتم حل التعارضات في Server Actions، ومشغل الصوت، وحارس المصادقة.

تم استخدام نوع قاعدة البيانات الرسمي في إدخال طلب الحجز، وأصبح TypeScript يمر بنجاح. وتم إصلاح استدعاءات Hooks المشروطة في مشغل الصوت. كما تم توحيد مسارات الصور القديمة القادمة من Supabase مع أصول Figma المحلية.

تمت إزالة الشكل البيضاوي من صورة About لأن مواصفة Figma المحلية تشير إلى صورة مستقلة بلا إطار أو chrome. وتمت معالجة تحذيرات نسبة أبعاد الصور في Navbar وAbout بقدر ما يسمح به مكوّن Next Image.

تمت إضافة التعريب والمسارات المحلية، وأصبح Production Build يولّد مسارات عربية مثل:

```text
/ar
/ar/academy
/ar/artists
/ar/events
/ar/news
/ar/booking
```

## أسباب الفروقات المتبقية

### 1. الخط الأصلي غير متوفر

الواجهة تستخدم fallback إلى Cairo لأن ملف Qahwa Arabic الأصلي غير موجود حاليًا في `public/assets/fonts`. اختلاف الخط يغيّر عرض العناوين، التفاف الأسطر، ارتفاع الأقسام، ومواقع العناصر التابعة.

**الحل:** توفير ملف الخط المرخّص من Figma أو التصميم، ثم تعريفه في `@font-face`، والتأكد من وزن الخط وتباعده وارتفاع السطر.

### 2. مرجع Figma المباشر غير متاح حاليًا

محاولة قراءة ملف Figma عبر API أعادت `403 Token expired`. لذلك القياسات الحالية تعتمد على مراجع Figma المحلية المحفوظة في المستودع، وليس على آخر نسخة مباشرة من Dev Mode.

**الحل:** تجديد Figma API connector، ثم إعادة استخراج العقد والصور والقيم من الملف الحالي قبل ضبط التفاصيل النهائية.

### 3. أصول وصور غير موحدة بالكامل

تم توحيد صور Hero وAbout، لكن بقية الصفحات ما زالت تعتمد على أصول seed أو fallback. اختلاف الصورة وحده يغيّر نسبة كبيرة من البكسلات حتى لو كان التخطيط صحيحًا.

**الحل:** بناء جدول لكل `imageRef` في Figma وربطه بالصورة المقابلة في CMS، مع ضبط `object-fit` و`object-position` لكل صورة.

### 4. البيانات الظاهرة في CMS قد تختلف عن Figma

عدد العناصر، النصوص، أسماء الفنانين، التواريخ، المقالات، والتقييمات قد تختلف عن البيانات الموجودة في Frame المرجعي.

**الحل:** إنشاء fixture ثابت للمقارنة البصرية أو seed مطابق حرفيًا لنسخة Figma، ثم تشغيل اللقطات من نفس البيانات في كل مرة.

### 5. المقارنة لا تغطي كل الحالات

التقرير الحالي لا يقيس معظم صفحات Mobile، ولا صفحات الإدارة، ولا تسجيل الدخول، ولا تفاصيل الأخبار.

**الحل:** إضافة manifest كامل لكل route ومقاس، مع لقطات Desktop وMobile وحالات loading وempty وerror عند الحاجة.

## خطة الحل التنفيذية

### المرحلة الأولى: تثبيت المرجع

1. تجديد Figma API token.
2. قراءة ملف Figma الحالي والتأكد من العقدة الرئيسية.
3. تحديث `docs/figma-reference-manifest.json`.
4. استخراج node specs لكل صفحة.
5. استخراج الأصول الأصلية وربطها بأسماء ثابتة.
6. تثبيت نسخة Figma ورقمها في التقرير.

**معيار الإنجاز:** لا توجد صفحة في manifest بلا `nodeId` أو مرجع صورة أو أبعاد واضحة.

### المرحلة الثانية: تثبيت الخطوط وtokens

1. إضافة Qahwa Arabic الأصلي.
2. مقارنة أوزان Cairo وQahwa مع Figma.
3. تثبيت الألوان في `globals.css`.
4. تثبيت الحاويات، التباعد، radii، shadows، وأحجام الأزرار.
5. إزالة القيم المتعارضة الموجودة داخل المكونات.

**معيار الإنجاز:** يطابق عنوان تجريبي في المتصفح عرض وارتفاع عنوان Figma ضمن فرق لا يتجاوز 1px.

### المرحلة الثالثة: إصلاح المكونات المشتركة

يبدأ الإصلاح بالمكونات التي تؤثر على كل الصفحات:

1. Navbar وMobileNavbar.
2. Footer.
3. PublicButton.
4. PageHero وHeroSection.
5. Card primitives.
6. Filter tabs.
7. Image wrappers.
8. Locale switcher.

**معيار الإنجاز:** مطابقة مكونات Header وFooter في كل routes قبل تعديل محتوى الصفحات.

بعد ذلك يتم تشغيل:

```bash

npm test

npm run visual:screenshots
npm run visual:diff
```
